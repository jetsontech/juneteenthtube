# JuneteenthTube Observability & Telemetry Report

This document reports the launch-ready observability and real-time telemetry framework for JuneteenthTube, specifying Sentry failure capture configurations and playback/upload analytical tracking pipelines.

---

## 1. Sentry Integration Config

We configured the standard Sentry SDK framework for Next.js to isolate and capture production exceptions:

```
[Next.js Application Exception]
              ↓
  [Sentry Serverless Handler]
              ↓
[Sentry Cloud Platform (Issues Log)]
```

### Captured failure types

* **Frontend**: Unhandled React boundary errors, hydration mismatches, client-side route navigation fails, chunk loading exceptions.
* **Backend**: S3/R2 presigned signature timeouts, DB lookup failures in Serverless routes, transcoder dispatch timeouts.

## 2. Telemetry Database Schema

Playback telemetry events are stored directly in the `analytics_events` table:

```sql
create table if not exists public.analytics_events (
  id bigint generated by default as identity primary key,
  event_type text not null, -- 'playback_start', 'playback_stop', 'buffering_start', 'buffering_end', 'playback_error', 'quality_change', 'abandonment', 'watch_complete', 'upload_start', 'upload_complete', 'upload_error', 'transcode_start', 'transcode_complete', 'thumbnail_gen'
  video_id uuid references public.videos(id) on delete cascade,
  user_id uuid references auth.users(id) on delete set null,
  guest_id text,
  details jsonb default '{}'::jsonb not null, -- Stores metadata like buffering duration, selected quality, error message, upload size, transcode time, etc.
  created_at timestamp with time zone default timezone('utc'::text, now()) not null
);
```

## 3. Playback Analytics Events

The custom HTML5 player triggers telemetry events to `POST /api/telemetry` at key milestones:

* **Player Start**: Triggered on `playing` event when media starts. Captures startup time (time from load to first frames).
* **Player Stop / Pause**: Captures the exact playback offset.
* **Buffering Start**: Fired on `waiting` event. Captures buffer start timestamp.
* **Buffering End**: Fired on subsequent `playing` event. Computes and logs exact buffering delay.
* **Playback Failure**: Captures the explicit HTML5 player error code and details.
* **Quality Changes**: Records toggles between `optimized` (H.264) and `master` (Ultra HD) streams.
* **Abandonment**: Captured if the viewer unmounts or exits the page before completion.
* **Watch Completion**: Logged when the video reaches `ended` status.

## 4. Operational Telemetry Dashboards

We designed two high-fidelity telemetry dashboards using Supabase queries:

### A. Playback Analytics Dashboard

* **Startup Time**: Average time-to-first-frame (target: `<800ms`).
* **Buffering Ratio**: Percentage of watch time spent in buffering state (target: `<1.5%`).
* **Completion Rate**: Ratio of watch completions relative to plays (measures engagement quality).
* **Error Rate**: Percentage of plays encountering a `playback_error` event (target: `<0.1%`).

### B. Creator Operations Dashboard

* **Upload Success Rate**: Successful Cloudflare R2 transfers vs. failures (target: `>99%`).
* **Average Upload Time**: Measured across single and multipart chunks.
* **Transcode Success Rate**: Percentage of video assets processed into optimized H.264 streams without errors.
