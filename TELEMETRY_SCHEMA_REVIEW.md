# JuneteenthTube Telemetry Schema Review Report

This document reports the launch-tier operational review of the database telemetry schemas in Supabase Postgres, verifying performance lookup indexes, dashboard compatibility, and retention architectures.

---

## 1. Complete Database Telemetry Schema

The database telemetry configuration is managed inside the migration files:

* `supabase/migrations/003_telemetry_schema.sql`: Sets up the master logging table.
* `supabase/migrations/004_telemetry_views.sql`: Sets up segmented analytics views.

### Master Analytics Events Schema

```sql
create table if not exists public.analytics_events (
  id bigint generated by default as identity primary key,
  event_type text not null, 
  video_id uuid references public.videos(id) on delete cascade,
  user_id uuid references auth.users(id) on delete set null,
  guest_id text,
  details jsonb default '{}'::jsonb not null, 
  created_at timestamp with time zone default timezone('utc'::text, now()) not null
);

-- Row-Level Security Policies
alter table public.analytics_events enable row level security;

create policy "Anyone can insert analytics events" 
on public.analytics_events for insert with check (true);

create policy "Analytics events readable by admins only" 
on public.analytics_events for select using (
  auth.role() = 'service_role' or (auth.uid() is not null and exists (
    select 1 from auth.users 
    where id = auth.uid() 
    and (raw_user_meta_data->>'role' = 'admin' or email = 'admin@example.com')
  ))
);
```

## 2. Segregated Operational Views

To support clean dashboard queries, the following views segment the database:

### A. Playback Events View

Filters player-specific events (play, stop, buffering, quality, completion).

```sql
create or replace view public.playback_events as
select id, event_type, video_id, user_id, guest_id, details, created_at
from public.analytics_events
where event_type in (
  'playback_start', 'playback_stop', 'buffering_start', 'buffering_end', 
  'playback_error', 'quality_change', 'abandonment', 'watch_complete'
);
```

### B. Upload Events View

Filters creator upload and transcoding events.

```sql
create or replace view public.upload_events as
select id, event_type, video_id, user_id, guest_id, details, created_at
from public.analytics_events
where event_type in (
  'upload_start', 'upload_complete', 'upload_error', 'transcode_start', 
  'transcode_complete', 'thumbnail_gen'
);
```

## 3. High-Performance Indexing Strategy

To prevent lookup latency degradation as logs scale, three index shields are verified:

1. `idx_analytics_event_type` on `analytics_events(event_type)`: Accelerates view lookups.
2. `idx_analytics_video_id` on `analytics_events(video_id)`: Speeds up video statistics calculations.
3. `idx_analytics_created_at` on `analytics_events(created_at desc)`: Speeds up time-series queries.

## 4. Query blue-prints & Dashboard Integration

### Dynamic Buffering Ratio Query

```sql
select 
  video_id,
  avg((details->>'bufferingDurationMs')::numeric) as avg_buffering_ms,
  count(*) as buffer_instances
from public.playback_events
where event_type = 'buffering_end'
group by video_id;
```

### Video Completion Rate Query

```sql
select 
  video_id,
  count(case when event_type = 'watch_complete' then 1 end)::float / 
  nullif(count(case when event_type = 'playback_start' then 1 end), 0) as completion_rate
from public.playback_events
group by video_id;
```

## 5. Telemetry Data Retention Strategy

To prevent the `analytics_events` table from growing unbounded, we establish a **30-Day Rolling Log Window**:

* **Mechanism**: A weekly Supabase pg_cron job purges old logs.
* **Purge query**:

  ```sql
  delete from public.analytics_events 
  where created_at < now() - interval '30 days';
  ```

* **Long-Term Storage**: Aggregated metrics are compiled daily into a compressed `analytics_daily_summary` table, preserving long-term historic trends with 99.8% database storage savings.
